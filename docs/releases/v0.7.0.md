# v0.7.0 — Portable installation: move the folder and keep the build

**v0.7.0 · 2026-11-16 · [Changelog](https://github.com/Vnnc1/gow-native-pc/blob/main/CHANGELOG.md)**

A native PC port of **God of War (PS2)**. The game's executable is statically recompiled from MIPS to C++ and built on your machine from your own compatible disc image. **No game files are included or downloaded.**

v0.7.0 makes an installation portable. Everything it records about itself — the build folder, the disc, the language ELFs — is now stored relative to its own folder, so copying or moving an installation keeps working instead of losing its build. The launcher recognizes an installation whose build folder belongs to another project folder, explains it instead of reporting "not installed", and offers the rebuild; an existing installation can also point its build at the project folder from the Install page, without running the setup again.

**The project is still in development.** Stable 60 FPS remains the target; performance depends on hardware, settings and the scene.

## Download

- **`gow-native-pc-setup.exe` — Windows, recommended:** installs or updates the launcher for your user, without administrator rights.
- **`gow-native-pc-windows.zip`:** the Windows distribution without the installer (also used by the launcher's automatic update).
- **`gow-native-pc-linux-x86_64-ubuntu24.04-experimental.run` — Linux, experimental:** installs the native launcher and build scripts.
- **`gow-native-pc-linux-x86_64-ubuntu24.04-experimental.tar.gz`:** the same Linux distribution for manual extraction.
- **`SHA256SUMS.txt`:** checksums of every file above.

**Updating an existing Windows installation (v0.6.1 or older)?** Run the setup over its current folder, or accept the update offered by the launcher. Your discs, saves and settings are kept. **Rebuild the game when the launcher asks**: this release changes how the runner finds the disc it is given (patch 25), and a runner built by an older launcher does not understand the relative disc path the new launcher records.

## How to play

### Windows

1. Run `gow-native-pc-setup.exe` and open **God of War Launcher**. The setup builds the game in `<installation>\build` by default; **Build folder → Change** on the Install page moves it.
2. In **Install**: **Download tools → Add ISO / CHD… → Install and build**.
3. Keep **Prepare the first play** enabled: it records the game's VU1/IOP code once and builds it in as native code.
4. Choose your graphics settings, review Controls and Accessibility, then click **PLAY**.

### Linux — experimental

Install the system dependencies described in the [Linux guide](https://github.com/Vnnc1/gow-native-pc/blob/main/docs/linux.md), then run:

```bash
bash gow-native-pc-linux-x86_64-ubuntu24.04-experimental.run
bash "$HOME/.local/share/gow-native-pc-0.7.0/start-linux.sh"
```

Import your own compatible disc through the launcher's Install page to compile the game. The installer accepts a **new destination directory** as its argument and refuses existing destinations to protect games and saves. It does not install system dependencies.

**The supplied binaries use Ubuntu 24.04 libraries.** This is not a universal AppImage or a validated SteamOS package. Other distributions may require rebuilding the launcher from source.

## Requirements

- **Windows:** Windows 10/11 64-bit.
- **Linux:** experimental x86-64 support; see the distribution-specific dependencies in the Linux guide.
- **CPU:** x86-64-v2, including SSE4.2/POPCNT.
- **RAM:** 8 GB; 16 GB recommended while compiling.
- **GPU:** OpenGL 4.3+ with the manufacturer's driver (a software renderer remains as a fallback).
- **Game:** your own compatible God of War disc image.

## What's new since v0.6.1

### Portable installation

- **The build folder is recorded relative to the project** (`data/build-root.txt`). Renaming the installation folder or copying the whole installation keeps its build; a build root outside the project — the short `C:\gow-build` fallback for long paths, or another drive — stays absolute, because no portable record can describe it.
- **The disc and the language ELFs are recorded the same way.** The launcher writes the disc into `gow-native.boot` relative to the runner's folder and the runner resolves it there (patch 25), so a moved installation boots its own disc instead of stopping with "the disc recorded in gow-native.boot is missing".
- **Moving the folder still needs a rebuild, and says so:** CMake's cache keeps absolute paths, so the pipeline treats a cache made in another folder as foreign and builds again in `build-<hash>`, keeping the previous build folder and your saves. Nothing is presented as relocatable that is not.

### Launcher

- **Moved installation:** a build folder inside the installation whose CMake cache names another project folder is reported as moved. The Install page explains it and offers the rebuild, and the Home status line says so instead of "not installed" — which is exactly how a copied installation used to look.
- **Build folder → Change:** an existing installation can point its build at the project folder without rerunning the setup. The picker refuses the installation folder itself, a base whose build path would exceed the pipeline's budget and a cache made by another copy, and it maps a picked `build-clang` back to `build`. It never moves an existing build, because CMake's cache cannot leave its folder. Windows only: on Linux the pipeline always builds under `data/build-linux/<game>`.
- The new texts are in all nine launcher languages.

## Known limitations

- **This Windows build ships without the PGO profile.** It is produced by CI, which has no game to train on, so these binaries are not profile-guided. A local build trains its own: `build.cmd -Stages fetch,configure,recomp,sync,pgo`.
- Heavy combat and slower CPUs can still run below 60 FPS; the ship's storm section is CPU (VU1) bound.
- Freeze after the Cronos climb cutscene (#33) is not fixed yet; the next diagnostic report will identify its cause.
- Europe/Japan builds still lack the movie end-of-file fix from #30.
- Shake (wiggle) stick prompts have no keyboard guide yet.
- Only a build folder inside the installation is reported as moved. One chosen elsewhere belongs to whichever copy configured it and stays rejected by the runner's ownership check.
- Linux remains experimental and depends on compatible system libraries; real Steam Deck gameplay is unvalidated.

Report problems in [Issues](https://github.com/Vnnc1/gow-native-pc/issues). Use **Other → Mark a problem during play**, then export a ZIP through **Other → Test and bug report**. Include your CPU, GPU, operating system, disc edition and whether a texture pack was enabled.
